# 国际贸易网站前端三模板改造与发布计划

## 1. 目标

- 保留现有 Payload 管理后台、权限、商品/文章/媒体管理、多语言、翻译工作流和发布流程。
- 在同一套代码和同一套内容模型上提供 3 个固定前端模板，客户最终三选一。
- 模板只允许在 `trust`、`catalog`、`solution` 三个白名单值中选择，不提供自由组合、模板上传或第四套模板开发入口。
- 前端素材只使用服务器上客户当前已经上传到项目媒体库/对象存储的素材；不使用参考站点的图片、文案、Logo、代码、仓库旧 SQLite 数据或演示图库。
- 先在本地完成开发、运行和逐页面视觉验收；验收全部通过后，才允许同步服务器。

## 2. 范围与边界

### 包含

- 现有模板整理为 `trust` 基准模板。
- 新增 `catalog` 产品目录型模板。
- 新增 `solution` 方案内容型模板。
- 共享数据查询、SEO、国际化、Header/Footer、媒体处理、询盘入口、商品卡片和文章渲染能力。
- 为 B 端产品页补充或规范 MOQ、样品、交期、材质、包装、认证、目标市场、定制能力等字段；具体字段以真实业务资料为准。
- 本地预览、截图、交互、可访问性、响应式、链接和构建验收。

### 不包含

- 不重写现有管理后台。
- 不复制参考网站的页面、文案、图片、商标或代码。
- 不允许客户在后台创建新模板或自由拼装新的页面布局。
- 不在未完成本地验收前修改生产服务器。
- 不把不确定的工厂数据、认证、MOQ、交期或客户案例写成页面事实。

## 3. 模板定义

### `trust`：信任背书型

适合大多数 B2B 客户，突出工厂实力、认证、质检、交付流程、服务能力和询盘 CTA。当前首页视觉方向作为基准，补强产品分类、信任证明和采购信息。

### `catalog`：产品目录型

适合 SKU 较多、经销商或批发采购场景。突出分类、筛选、产品网格、规格摘要、MOQ、下载目录和询价入口；移动端必须保持可用，不能依赖悬停操作。

### `solution`：方案内容型

适合 OEM/ODM、工程项目和高客单价产品。突出行业场景、解决方案、案例、生产流程、合规指南、采购文章和项目咨询入口。

三个模板必须在首屏布局、导航、产品展示方式、信任区、内容区和 CTA 组织上有实际差异，而不是只替换颜色或字体。

## 4. 技术架构

```text
Payload 后台 / 统一内容模型 / 多语言
              ↓
       公共 View Model 适配层
              ↓
       固定模板注册器
       ├── trust
       ├── catalog
       └── solution
```

建议目录：

```text
src/templates/
  trust/
  catalog/
  solution/

src/components/shared/
  Header/
  Footer/
  ProductCard/
  InquiryCTA/
  FAQ/
  SEO/
  Media/
```

- Payload 查询、缓存、权限和翻译逻辑保持在共享层。
- 模板只接收统一的页面 View Model，不直接依赖 Payload 原始文档结构。
- 继续使用现有的 locale 路由和 App Router；模板切换不能改变公开 URL，避免 SEO 地址失效。
- 模板配置单独使用 `SITE_TEMPLATE` 或 `SiteSettings.templateKey`。现有 `SITE_VARIANT=blank/demo` 继续只负责空站/演示站，不与模板选择混用。
- 生产环境只接受三个枚举值；未知值回退到 `trust` 并记录错误。

### 模板选择方式

- 单客户、单域名、交付前确定：优先使用部署级 `SITE_TEMPLATE`，稳定且适合当前静态缓存页面。
- 客户要求通过后台切换：增加受权限保护的 `SiteSettings.templateKey` 单选字段，并为修改增加缓存刷新/重新验证。
- 两种方式只选一种作为唯一真源，不同时读取环境变量和数据库配置。
- 允许内部预览其他模板，但预览 URL 不参与 canonical、sitemap 或搜索索引。

## 5. 数据源、内容和素材规则

- 服务器上的客户数据库和媒体对象存储是本次改造的唯一内容来源。
- 本地仓库中的 `*.db` 文件只作为旧数据/测试资料，不得作为本次模板开发和视觉验收的数据源。
- 本地开发前先从服务器生成一次只读数据快照和媒体副本；快照必须记录生成时间、源环境、数据/媒体数量和校验和。
- 本地验收期间不反向写入服务器，不直接修改服务器商品、文章、公司资料或媒体。
- 如果当前没有安全的服务器快照/媒体导出通道，先补齐只读导出或由客户提供已脱敏的数据库与媒体归档；未获得服务器数据前不得用仓库旧数据替代。

- 商品、文章、公司资料、媒体图片均从服务器生成的本地快照读取。
- 禁止继续使用 demo 产品的远程图片作为正式站 fallback；缺少素材时显示可识别的空状态并列入验收问题。
- 图片必须保留客户媒体库中的 alt 文本；缺失时在后台补充，不用标题机械生成所有 alt。
- 认证、工厂面积、产能、客户 Logo、出口国家、交期和 MOQ 必须有客户资料或文件依据。
- 结构化数据只标记页面上可见且已确认的内容；FAQ 必须与页面实际展示的问题和答案一致。
- 参考站点只用于信息架构和 B2B 内容方向，不复制其关键词堆叠、图片、文案或数字。

## 6. 页面范围

第一阶段至少覆盖以下公共页面，并对每个已发布实际 URL 验收：

- 首页：`/{locale}`
- 商品列表/目录页：现有入口及新增分类入口
- 商品详情页：`/{locale}/products/{slug}`
- 文章列表页：`/{locale}/posts`
- 文章详情页：`/{locale}/posts/{slug}`
- 询盘/联系我们相关入口、弹窗和错误状态
- 语言切换、导航菜单、移动端菜单、返回链接、分页、商品图片画廊
- robots、sitemap、canonical、hreflang 和结构化数据输出

如果开发阶段新增分类、市场、合规、案例或下载页，这些页面自动纳入同一验收矩阵，不能只验收首页。

## 7. 实施阶段和门禁

### 阶段 0：基线、数据快照与授权确认

- 检查开源项目 LICENSE、依赖许可证、现有图片/字体/图标授权和客户素材使用范围。
- 记录当前工作区已有修改，不覆盖与本任务无关的文件。
- 从服务器生成只读数据库快照和媒体归档，完成数量、文件存在性、MIME、校验和及商品图片关系预检。
- 保留原始服务器数据不动；所有本地修复只作用于快照副本，并记录为待客户确认事项。
- 确认客户产品线、目标买家、目标市场和可公开的工厂数据。
- 输出页面清单、内容字段清单和三模板线框稿。

**门禁：**素材来源、产品定位和模板边界明确后才进入开发。

### 阶段 1：共享层和内容模型

- 统一商品、公司、文章、FAQ、认证和询盘 View Model。
- 补充确有资料支持的 B2B 字段。
- 抽离共享 Header/Footer、媒体、SEO、CTA、商品卡片和文章组件。
- 保持后台权限、草稿/发布、翻译和媒体管理行为不变。

**门禁：**现有后台可以正常编辑/发布，旧路由和多语言数据不丢失。

### 阶段 2：三套前端模板

- 先完成 `trust` 基准模板。
- 再完成 `catalog` 和 `solution`，复用共享数据层和组件。
- 每套模板都覆盖首页、商品列表/详情、文章列表/详情、询盘入口和移动端导航。
- 所有颜色、间距、字体和动效使用模板级 token；不在页面中散落硬编码。

### 阶段 3：本地运行和视觉验收

- 使用服务器快照和客户媒体副本运行本地环境，不连接生产数据库做页面开发。
- 使用 Playwright 从 sitemap/公开路由自动收集实际页面 URL。
- 对每个模板、每个页面类型、每个实际子页面，在 375、768、1024、1440 宽度下截图。
- 同时检查桌面端、移动端、横屏、键盘操作、焦点状态、表单反馈、图片加载、空数据和错误状态。
- 记录每张截图对应的 URL、模板、语言、视口、问题、严重级别、修复状态和复验结果。

**视觉 PASS 条件：**无重叠、截断、横向滚动、错位、空白大洞、缺失客户素材、不可读文字、失效链接、控制台错误或关键交互故障；图片 alt、焦点、表单错误提示、响应式和减少动效行为均通过检查。

### 阶段 4：客户三选一和锁定

- 提供三套本地预览和验收报告。
- 客户选择一个正式模板并确认。
- 锁定模板键；后续只接受 Logo、颜色 token、文案、图片、商品和后台内容调整。
- 新布局、新组件、混合模板、第四套模板和逐页定制列为额外需求。

### 阶段 5：服务器同步

只有以下条件全部满足才执行：

- 三套模板本地构建通过，正式选择模板已锁定。
- 所有公开页面和子页面视觉验收 PASS。
- lint、typecheck、集成测试、E2E、生产构建通过。
- sitemap、canonical、hreflang、robots、JSON-LD 和图片 alt 检查通过。
- 客户素材完整性检查通过，未混入仓库旧数据、demo 或外部示例素材；本地快照校验和与记录一致。
- 已备份生产数据库和媒体索引，并确认可回滚版本。
- 服务器环境变量、数据库迁移、对象存储和缓存策略已核对。

同步后只做一次线上冒烟检查：首页、一个商品列表、一个商品详情、一个文章详情、询盘入口、语言切换、后台登录和媒体加载。发现阻断问题时立即回滚到验收通过版本。

## 8. 视觉验收报告格式

每个问题至少记录：

```text
模板：trust / catalog / solution
页面：完整 URL
语言：locale
视口：width × height
问题：可复现描述
严重级别：P0 / P1 / P2 / P3
截图：本地验收截图路径
修复：提交或文件位置
复验：PASS / FAILED
```

服务器同步前必须生成一份最终报告，包含页面总数、模板、语言、视口、通过数、失败数、修复次数、遗留问题和最终选择的模板键。

## 9. 完成定义

本项目只有在“客户选定一个固定模板 + 本地所有实际页面视觉验收通过 + 自动化检查通过 + 生产备份和回滚方案确认”后，才算完成。未满足条件时保持本地状态，不同步服务器。
